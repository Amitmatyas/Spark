# SPARK: מערכת הסטודיו

שרת אחד שמריץ שלושה עמודים, כולם באותו עיצוב ניאון:

| כתובת | מה זה |
| --- | --- |
| `/` | דף הנחיתה. הטופס שומר פנייה ושולח ללקוח אישור בוואטסאפ. |
| `/admin` | עמוד המנהל: כניסה עם Google, פניות, תיקיות לקוחות, סרטונים, משימות, פתקים, צ'אט וואטסאפ והגדרות. |
| `/c/<קישור>` | האזור האישי של כל לקוח: כניסה עם קוד בוואטסאפ, צפייה והורדה של הסרטונים שלו. |

## איך זה עובד

1. מישהו משאיר פרטים באתר. הפנייה נשמרת והוא מקבל בוואטסאפ: "קיבלנו את הפרטים שלך ונחזור אליך בקרוב".
2. בעמוד המנהל קופצת התראה עם צליל: **שיחה**, **וואטסאפ** או **מילוי פרטים**.
3. אחרי השיחה, "מילוי פרטים" מכניס את הלקוח למערכת ופותח לו תיקייה בדרייב (חדשה, או אחת שכבר קיימת).
4. בתיקיית הלקוח: מעלים סרטונים (הם עולים לדרייב), כותבים משימות ופתקים, ומתכתבים איתו בוואטסאפ עם כל ההיסטוריה.
   לפני ההעלאה אפשר לכתוב הערות ללקוח. בסוף ההעלאה הוא מקבל הודעת וואטסאפ שעלה סרטון חדש, עם ההערות (אם יש) וקישור, וההערות מופיעות גם מתחת לסרטון באזור האישי.
5. "שליחת קישור לאזור האישי" שולח ללקוח קישור. בכניסה הראשונה הוא מקבל קוד בוואטסאפ, ומאז המכשיר זוכר אותו עד שהוא לוחץ על התנתקות.

## התראות

- על כל פנייה חדשה מגיעה הודעת וואטסאפ לטלפון שלך (לצ'אט "הודעה לעצמי"), עם השם, הטלפון וקישור לניהול. מכבים או משנים מספר בהגדרות.
- **התראות במכשיר (Push):** בהגדרות ← "הפעלת התראות במכשיר הזה". פנייה או הודעה חדשה קופצות על המסך גם כשהניהול סגור. מפעילים בכל מכשיר בנפרד.
  - במחשב: עובד ב-Chrome, Edge ו-Safari, כל עוד הדפדפן פתוח (גם בלי חלון של הניהול).
  - באייפון: רק אחרי שהאתר בשרת עם HTTPS. פותחים את `/admin` בספארי ← שיתוף ← "הוספה למסך הבית", נכנסים מהאייקון ומפעילים שם. באנדרואיד עובד ישר מ-Chrome.
- כפתור וואטסאפ צף באתר ובאזור האישי פותח שיחה עם מספר הסטודיו (ברירת מחדל: המספר שמחובר למערכת).

## הפעלה

צריך Node 22.13 ומעלה. לא צריך דפדפן: וואטסאפ מתחבר דרך Baileys. להתקנה על NAS עם Docker ראו `NAS.md`.

```bash
npm install
npm start
```

לפתוח את http://localhost:3000/admin ולהתחבר עם Google.

**חיבור וואטסאפ (פעם אחת):** בעמוד המנהל ← הגדרות מופיע QR. בטלפון של הסטודיו: וואטסאפ ← הגדרות ← מכשירים מקושרים ← קישור מכשיר, וסורקים. החיבור נשמר ב-`data/wa-baileys`, אז אחרי הפעלה מחדש לא צריך לסרוק שוב.

## הגדרות (`.env`)

| משתנה | מה הוא עושה |
| --- | --- |
| `ADMIN_EMAILS` | חשבונות Google שמורשים להיכנס לניהול, מופרדים בפסיק. |
| `PUBLIC_URL` | הכתובת שהלקוחות מגיעים אליה. ממנה נבנים הקישורים לאזור האישי וחזרת ההתחברות מ-Google. |
| `PORT` | הפורט של השרת (ברירת מחדל 3000). |
| `DRIVE_PARENT_FOLDER_ID` | תיקיית Spark בדרייב, שבתוכה נפתחת תיקייה לכל לקוח. |
| `WA_DISABLED` | `1` מכבה את וואטסאפ. |
| `WA_DEBUG` | `1` מדפיס בלוג אזהרות ושגיאות של חיבור הוואטסאפ. |

את נוסח ההודעות האוטומטיות (אישור פנייה, קישור לאזור האישי, קוד כניסה) עורכים בעמוד המנהל ← הגדרות.

## Google

- ההתחברות לניהול והחיבור לדרייב משתמשים באותו `oauth-client.json`. מי שמתחבר ראשון, כשהדרייב עוד לא מחובר, מחבר גם את הדרייב. מנהל נוסף שמתחבר אחר כך לא מחליף אותו.
- ב-Google Cloud Console ← Credentials ← ה-OAuth client, צריך להופיע Redirect URI ‏`<PUBLIC_URL>/oauth2callback`. ‏`http://localhost:3000/oauth2callback` כבר רשום.
- כל עוד מסך ההסכמה (OAuth consent screen) במצב **Testing**, רק חשבונות שמופיעים תחת Test users יכולים להתחבר, וההתחברות פגה אחרי 7 ימים. כדי להימנע מזה מעבירים אותו ל-**In production**.

## לפני שעולים לאוויר

ההוראות המלאות להעלאה לשרת נמצאות ב-[DEPLOY.md](DEPLOY.md).


- **השרת צריך להיות זמין ללקוחות.** ב-`localhost` רק המחשב הזה רואה את האתר. בשביל לקוחות אמיתיים מריצים את השרת על שרת קבוע (VPS או NAS, ראו `NAS.md`), או חושפים את המחשב דרך מנהרה כמו Cloudflare Tunnel. אחר כך מעדכנים את `PUBLIC_URL` ומוסיפים את ה-Redirect URI ב-Google.
- **וואטסאפ דרך Baileys הוא לא ה-API הרשמי.** הוא מתחבר כמו וואטסאפ ווב (מכשיר מקושר), והמחשב או השרת צריכים להישאר דולקים. כדאי לחבר מספר עסקי ולא לשלוח הודעות שיווק המוניות, כי וואטסאפ עלול לחסום מספרים שנראים כמו ספאם.
- הודעות שלא יצאו כי וואטסאפ היה מנותק נשמרות ונשלחות כשהוא מתחבר, עד 24 שעות אחרי שנכתבו. קודי כניסה לא נשמרים לשליחה מאוחרת.

## איפה הכול נשמר

- `data/spark.db`: פניות, לקוחות, משימות, פתקים והיסטוריית הודעות (SQLite). עותק נשמר כל יום ב-`data/backups` (14 הימים האחרונים).
- `data/wa-baileys`: החיבור לוואטסאפ.
- `data/token.json`: החיבור לדרייב (קובץ `token.json` ישן בתיקייה הראשית מועבר לשם לבד).
- הסרטונים נשמרים רק בדרייב, בתיקייה של כל לקוח. לקוח רואה כל סרטון שנמצא בתיקייה שלו, גם כזה שהועלה ישירות לדרייב.
- `oauth-client.json`, `data/token.json`, `service-account.json` ו-`.env` הם סודות. הם ב-`.gitignore` ואסור לשתף אותם.

## דף הנחיתה

דף הנחיתה נמצא ב-`public/index.html`, והטופס שבו כבר שולח ל-`/api/leads`. הסרטונים והתמונות שלו ב-`public/media`.

ב-Vercel הדף מתארח כקבצים סטטיים (`vercel.json`): בבנייה `__SITE_URL__` מוחלף בכתובת של האתר, כדי שהתצוגה המקדימה בוואטסאפ ובפייסבוק תעבוד, והכתובות `/admin`, `/c/...` וההתחברות עוברות לשרת ב-NAS.
